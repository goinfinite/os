Container bootstrap and internal setup including runtime directory creation, web server initialization, and NGINX configuration.

## Summary

- containerBootstrap.go — Container bootstrap orchestration (ContainerBootstrap)
- primaryVirtualHostSynchronizer.go — Syncs PRIMARY_VHOST across the NGINX conf, the PHP virtual host conf, and the database; skips the PHP step when php-webserver is not installed
- webServerSetup.go — Web server configuration and startup; NGINX integration and management; port and SSL binding; sets the LSPHP child process and connection capacity from container memory and the web server worker count from the container CPU count, then restarts the php web server so the values load; the capacity step is skipped when the PHP installation check fails
- primaryVirtualHostSynchronizer_test.go — Uses shared `testHelpers.ReadPersistentDbSvc()` (panic-on-error contract); no t.Skip — `LoadEnvVars` is the gate (MustCompile-equivalent for test setup)
- webServerSetup_test.go — Tests the capacity calculator and the config file updater; asserts the computed caps, the rewritten settings, and untouched non-lsphp settings

## Constraints

- MUST NOT fail container setup when the PHP installation check fails; PHP is optional
- MUST chown only the web content and nginx log dirs to the web server user on first boot; /app itself stays root-owned with the group-writable sticky bit
- MUST restore root ownership of /app, /app/conf, the nginx conf and pki dirs on every start, so an upgraded container cannot keep web-server-owned configs
- MUST keep the shared toolchain dir owned by the web server user on every start, so nobody sessions can install tools

## Guidance

- SHOULD prefer sentinel error checks (`errors.Is`) over substring matching on `err.Error()`
