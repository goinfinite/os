Runtime environment management for various programming languages and frameworks. Manages PHP, Node.js, Python, and other runtime installations and configurations.

## Summary

- runtimeCmdRepo.go — applies PHP version, settings, module, and virtual host changes, removes PHP virtual host config on delete, then restarts and verifies the web server
- runtimeQueryRepo.go — reads installed PHP versions, active modules, settings, and virtual host conf paths
- runtimeCmdRepo_test.go — covers the PHP settings write path, the listener map line regex and per-vhost count, the virtual host block probe, the listener map mapping and double check, the map line and block removal, and the per-module update report
- runtimeQueryRepo_test.go — covers module discovery, settings parsing, and module asset reads

## Constraints

- MUST support multiple runtime versions
- MUST manage environment variables per runtime
- MUST expose only PHP modules listed for the selected package version
- MUST read a tool module status from its binary presence under the PHP bin directory, not from the PHP extension list
- MUST remove the tool module package when disabling a tool module
- MUST fail the module read when the PHP service assets do not list the requested version
- MUST fail the operation when the web server restart or the post-restart module read fails
- MUST report a per-module failure when post-restart verification finds the status unchanged
- MUST fail the settings update when every setting write failed
- MUST validate the web server config before every restart
- MUST restart the PHP web server only when a module change or a settings write actually succeeded
- MUST map every new PHP virtual host on every listener that maps the primary host, regardless of the primary map line form
- MUST fail the operation when no primary listener map line exists
- MUST repair a listener map line that is missing from any listener that maps the primary host
- MUST NOT duplicate a listener map line for a hostname that already has one in a listener
- MUST NOT append a virtualhost block that already exists
- MUST remove the listener map lines, virtualhost block, and conf file when deleting a PHP virtual host
- MUST write every PHP conf mutation through the tk file clerk
- MUST pass the accounts that own the target directory chain to every file clerk write
- MUST NOT append a PHP directive that is absent from the virtual host conf: the write fails instead

## Guidance

- SHOULD attempt every requested module before returning a partial-success report
- SHOULD reconcile desired against current module state in the use case; the repo applies the modules it is handed
