Terminal session infrastructure. A terminal multiplexer holds the sessions; tmux is the current implementation and its vocabulary is confined to TerminalMultiplexerClient. Every call runs as the account's Linux user, because root cannot talk to another user's multiplexer socket.

## Summary

- terminalMultiplexerClient.go — resolves the account user and owns every multiplexer command: create, set name, send command, kill, list and attach; also parses session listings and opens the attach PTY
- terminalSessionCmdRepo.go — creates, renames, kills and attaches terminal sessions named os-managed-<16-hex>
- terminalSessionQueryRepo.go — resolves the accounts to read (one by id or all), lists their sessions, then sorts and paginates

## Constraints

- MUST run the multiplexer with the owner's credentials and a clean environment (HOME, USER, LOGNAME, SHELL, MISE_DATA_DIR)
- MUST close the PTY to detach; the multiplexer session must survive
- MUST treat a missing multiplexer server as an empty list, not an error
- MUST keep the session display name in the tmux user option `@os-name`, so it lives and dies with the session and never touches a database
- MUST reject a session name carrying the `|` separator, so a name cannot shift the listing columns
- MUST kill the session when a post-create step fails, so a failed create never leaves a session behind

## Guidance

- SHOULD keep the session name prefix in one place (TerminalSessionNamePrefix)
- SHOULD keep the name option key in one place (terminalMultiplexerNameOption)
- SHOULD skip a malformed list line instead of failing the whole read
- SHOULD add multiplexer commands only on TerminalMultiplexerClient, so a different multiplexer means editing one file
