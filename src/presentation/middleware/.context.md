Shared presentation middleware used by both the API and the UI layers. It holds cross-cutting request processing that is not specific to either one.

## Summary

- baseHref.go — sets rootBasePath, apiBasePath, uiBasePath, and baseHref in the request context. The validated X-Base-Href header replaces the default base href

## Constraints

- The X-Base-Href header is untrusted client input. The app MUST validate it as a UrlPath before use, so redirect locations stay same-origin
- Only the deployment proxy may set X-Base-Href. The app MUST NOT trust the header without validation, because it cannot verify the writer

## Guidance

- Base href serves the HTML document. Base paths serve routing. Do not confuse them
- The deployment proxy strips its prefix from request URLs. The HTML document still needs that prefix in its base href. That is why the header exists
- The deployment proxy (Ez) SHOULD overwrite or strip X-Base-Href on inbound requests. A client that sets the header can only steer its own same-origin prefix. The team accepted that low risk on 2026-09-15 and plans the fix in the proxy project
