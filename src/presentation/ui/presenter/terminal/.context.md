Terminal sessions modal fragment. Renders a vertical session rail beside an xterm.js pane. The rail lists the sessions. Below the list it holds a new-session button and a gear button. The new-session button creates a session with the defaults. The gear button swaps the button row for the custom create form. The browser talks to the terminal WebSocket directly. The footer icon and the overview card open the sessions modal.

## Summary

- presenter.go — sessions modal fragment handler
- index.templ — the session workspace (rail and pane), the create-session form section and the pane placeholder
- state.js — `SessionTerminalManager` owns one xterm instance and WebSocket per attached session; the `terminal` Alpine component uses it and owns the session rail, the create-session form, the inline rename, the kill action and the open tabs

## Constraints

- MUST load xterm.js and addon-fit from jsDelivr with SRI hashes
- MUST reconnect a dropped socket and show a disconnected state
- MUST give every session row an attach, a rename and a kill control, so the rail is the single session switcher
- MUST create a session with the defaults from the new-session button, with no form in the path
- MUST expand the custom create form from the gear button and collapse it back to the button row on cancel
- MUST open the created session tab when the create runs inside the modal, and open the sessions modal on the created session when it runs outside the modal
- MUST dispatch `update:terminal-session` after every session mutation, so the overview tables refresh

## Guidance

- SHOULD register the Alpine components through UiToolset.RegisterAlpineState, since the fragments can load more than once
- SHOULD resolve a session label through resolveSessionLabel, which mirrors TerminalSession.ReadName
- SHOULD render the rename input through TerminalSessionRenameInput, so the rail and the overview table share one input
