Container-backed test system for Infinite OS. One entry point, `tests.sh`, reads `registry.yaml` and runs each registered test inside a disposable container built from the working tree.

## Summary

- tests.sh — Runner. Parses level/feature/scope filters, supports `list`, `clean`, `--jobs`, and `--rebuild`, builds the image, starts one container per feature, enforces timeouts, prints the summary.
- registry.yaml — Registry of features, scopes, levels, and run commands.
- golden.yaml — Golden latency budgets for CLI operations. The runner reads them and never rewrites them.
- lib/assert.sh — Assertion helpers and pass/fail accounting for test scripts.
- lib/cli.sh — Runs `os` commands through the container runtime and exposes the parsed JSON response.
- lib/container.sh — Container lifecycle: image build, container start/reuse/stop, port lookup, log export.
- lib/timing.sh — Records operation latencies and compares them with the golden budgets.
- artifacts/ — Per-run results, timings, and container logs. Ignored by git.
- account/, auth/, cron/, database/, marketplace/, o11y/, runtime/, services/, ssl/, vhost/ — Feature test scripts, one directory per registry feature.
- fixtures/ — Static test data, such as the SSH public key used by the account tests.

## Constraints

- MUST run Go unit tests inside the `test` stage image, never on the host.
- MUST keep `fast` level containers reusable and `standard`/`exhaustive` containers disposable.
- MUST use unique run identifiers in resource names so reused containers stay deterministic.
- MUST mount the host binary and source tree with `--security-opt label=disable` on test containers. SELinux relabeling breaks when the host rebuilds files or when containers run in parallel.
- MUST NOT weaken assertions or rewrite golden budgets to make a run pass.
- MUST NOT add `set -e` to test scripts. Assertions must continue after a failure; `finishTests` computes the exit code. `tests.sh` documents this deviation from `.agents/rules/code/shell.md`.

## Guidance

- SHOULD add new tests as feature scripts and register them in registry.yaml.
- SHOULD mark implementation-coupled suites `provisional: true`.
- SHOULD keep each test script self-contained: prove absence, create, verify state, delete, prove absence.
